# SkyRealm — реестр материалов и лицензий

**Проверено:** 2026-11-07 (повторная сверка по CI build run 42386455645)  
**Репозиторий:** `kisia319-cell/SkyRealm-PC-Launcher`, ветка `main`  
**Версия игры в исходниках:** 0.20.50.83  
**Назначение:** предварительный технический реестр перед коммерческим распространением, в том числе через Steam.

> Это техническая инвентаризация файлов репозитория, а не юридическое заключение и не гарантия отсутствия претензий третьих лиц. Владелец проекта сообщил, что материалы SkyRealm создавались в ходе совместной работы с ChatGPT. Это заявление зафиксировано как сведения владельца, но само по себе не заменяет исходники, историю создания, договоры и проверку бинарных файлов.

## 2. Бинарные изображения — требуется подтверждение происхождения

Следующие файлы включаются в сборку лаунчера:

- `realm.jpg` — используется на страницах лаунчера/галереи.
- `icon.png` — иконка приложения/ресурс лаунчера.
- `SkyRealm.ico` — иконка Windows EXE.

GitHub API в рамках этой проверки не предоставил содержимое этих бинарных файлов для визуального осмотра и проверки метаданных. Владелец сообщил, что материалы созданы в рамках работы с ChatGPT. Поэтому в реестре они отмечены как **заявленные владельцем собственные материалы, но технически не верифицированные**. Перед Steam-релизом следует сохранить исходные файлы/промпты или историю создания и проверить, что в изображениях нет чужих логотипов, персонажей, водяных знаков либо стоковых элементов.

### Важное ограничение по версиям

В предыдущем успешном CI build run 42386455645 (Windows x64, CPython 3.12.10) логи зафиксировали точный набор: pywebview 6.2.1, PyInstaller 6.22.3, psutil 7.2.2 и их разрешённые зависимости. Теперь этот набор закреплён в `requirements-build.txt`; CI и локальный `build_exe.bat` используют один lock-файл. Workflow дополнительно сохраняет `build-dependencies.txt` с фактическим `pip freeze` для каждого релиза. Это улучшает воспроизводимость, но всё ещё не заменяет инспекцию внутреннего содержимого EXE и лицензий каждого реально упакованного файла.

В portable ZIP теперь включаются этот реестр, `THIRD_PARTY_NOTICES.txt`, lock-файл и фактический `build-dependencies.txt`. В игровой ZIP также добавляются игровые версии реестра и notices. Перед каждым коммерческим релизом необходимо сохранить:
1. вывод `python --version`;
2. вывод `python -m pip freeze`;
3. `build-dependencies.txt` из конкретного релиза;
4. перечень файлов внутри каждого EXE/архива PyInstaller;
5. лицензии всех реально включённых runtime-пакетов и их транзитивных зависимостей.

Не считать пакет build-only зависимостью или runtime-зависимостью без проверки состава EXE.

## 4. Внешние сервисы и сетевые обращения

В исходниках обнаружены обращения к GitHub Releases/API и Supabase Edge Functions. Это внешние сервисы проекта, а не игровые модели, звуки или шрифты. Для Steam-релиза отдельно проверить условия использования этих сервисов, доступность серверов, обработку персональных данных, Privacy Policy и описание сетевых функций игры.

В игровых HTML/CSS/JS-файлах не обнаружено подключения библиотек через CDN, внешних картинок или удалённых шрифтов. Это утверждение относится к проверенному дереву исходников на дату выше.

- История происхождения материалов вне GitHub (например, генерации, исходные проекты и сторонние договоры).
